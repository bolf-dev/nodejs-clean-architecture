# Tech stack

## Decided

| Area               | Choice                                            | Notes                                                                 |
|--------------------|---------------------------------------------------|-----------------------------------------------------------------------|
| Runtime            | Node.js 24 LTS                                    | `node:24-alpine` image                                                |
| Language           | TypeScript 6, strict mode                         | ES modules, so relative imports end with `.js`                        |
| Framework          | NestJS 12 on Express                              | Not used in the domain layer (see [constitution](../constitution.md)) |
| CQRS               | `@nestjs/cqrs`                                    | Official NestJS module: command and query buses, used as in the [NestJS CQRS recipe](https://docs.nestjs.com/recipes/cqrs) |
| Request validation | `class-validator`, `class-transformer`            | Standard pairing with the NestJS `ValidationPipe`                     |
| Configuration      | `@nestjs/config`                                  | Environment variables, validated at startup                           |
| Database           | PostgreSQL 18                                     | `postgres:18-alpine` image                                            |
| ORM                | MikroORM 7 (`@mikro-orm/postgresql`, `@mikro-orm/nestjs`) | Data mapper with unit of work and identity map, the approach DDD expects. Mapping is defined with `EntitySchema` in infrastructure, so domain classes have no ORM decorators. Chosen over TypeORM (decorators in entities, uneven maintenance), Prisma (own generated models, no unit of work) and Drizzle / Kysely (query builders, repositories fully hand-written). |
| Migrations         | MikroORM migrations (`@mikro-orm/migrations`)     | Generated from the difference between mapping and database, reviewed and committed. The schema is changed only through migrations. |
| Identifiers        | UUID from Node.js `crypto.randomUUID()`           | Generated by the application, so an aggregate has its id before it is saved. Built into Node.js, no extra dependency. |
| Test database      | Separate `app_test` database in the same PostgreSQL container | Migrated before functional tests, cleaned between tests       |
| HTTP client        | built-in `fetch`                                  | Part of Node.js, no extra dependency                                  |
| Tests              | Vitest 4, Supertest                               | `*.spec.ts` next to the code, `*.e2e-spec.ts` in `test/`              |
| Lint & format      | oxlint, Prettier                                  |                                                                       |
| Containers         | Docker multi-stage build, Docker Compose          | `development` and `production` targets in `.docker/Dockerfile`        |
| Task runner        | `make`                                            | Every command runs in a container                                     |
| External F1 data   | [Jolpica F1 API](https://api.jolpi.ca/ergast/f1/) | Public, no API key, successor of the Ergast API                       |
